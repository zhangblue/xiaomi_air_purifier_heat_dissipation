# v0.1.0 GitHub Release 设计

## 目标与范围

发布项目首个 GitHub Release `v0.1.0`，对应 `pyproject.toml` 中的版本 `0.1.0`。从当前 `main` 的已验证提交构建并上传两个独立的可运行目录包：macOS arm64 和 Linux x86_64。Windows x64 本次不附包，也不声称已完成发行验收。

## 发行内容

Release 标题为“净化器温控 v0.1.0 — 首个跨平台源码与双平台运行包”。正文参考 Kafka Lens 的中文结构：更新亮点、主要功能、稳定性与安全、下载与部署、限制及完整变更。下载表列出两个压缩包及各自的 SHA-256 校验文件。首发版本的完整变更链接指向该 tag 的提交历史。

附件命名：

- `purifier-control-v0.1.0-macos-arm64.tar.gz` 与同名 `.sha256`
- `purifier-control-v0.1.0-linux-x86_64.tar.gz` 与同名 `.sha256`

每个压缩包顶层为单个对应平台的目录，内含完整 `app/`、启动与只读检查脚本、公开配置模板及说明文件。用户解压后应先复制配置模板、仅在目标机保存 token、运行只读 `check`，确认温度和设备型号后再手动 `run`。不提供登录自启。

## 构建与验证

macOS 包在当前 Apple Silicon Mac 上从现行源码重新构建；Linux 包在同一台 Mac 的 Linux amd64 容器中，仅使用公开源码暂存清单构建。不得直接复用可能过期的 `dist/` 目录。构建前后运行 Python 测试，并对包中程序执行只读 `--help`；检查二进制架构、脚本可执行位、包内文件清单和 SHA-256。不得运行真实净化器写控制。Linux 容器的只读启动验证不等于 Ubuntu 26.04 真机验收。

## 安全与发布顺序

归档内容不得含 `config.toml`、`.secrets`、token、`.git`、`.venv` 或本机缓存。对压缩包内容做路径审计，并检查样例配置没有私钥。发布前核对 GitHub 当前 tag/Release 不存在、远端分支状态与本地提交一致性。先推送经验证的 `main`，再创建并推送指向同一提交的 `v0.1.0` tag，最后创建 GitHub Release 并上传四个附件；若任何阶段失败，不把未验证产物标为发布完成。
