# 可迁移目录包设计

日期：2026-10-01

## 目标与边界

为现有手动运行的 `purifier-control` 提供构建工具。分别在 macOS 和 Windows 构建一个目录包，复制到同系统、同 CPU 架构且兼容的目标电脑后，无需再安装 Python、Python 包、.NET Runtime 或 `smctemp`，即可配置设备并手动运行 `check` / `run`。不增加登录自启、Linux 支持、远程管理或跨系统交叉编译。

目录包不能消除操作系统与硬件前提：目标电脑仍须能读取 CPU 传感器、能通过局域网连接净化器；Windows 某些机器可能需要由所有者单独安装 PawnIO 驱动。macOS 分发时应说明系统可能要求用户批准运行未签名程序；首次构建时校验 `smctemp` 的可迁移依赖与再分发条件，不能验证时应报错，而非宣称包可直接迁移。

## 方案选择

采用 PyInstaller 的单目录模式封装 Python 入口及其依赖。PyInstaller 不跨系统编译，Windows 与 macOS 分别在本机或同系统构建机执行。Windows 温度探针通过 `dotnet publish` 指定目标 RID 和 `--self-contained true`，连同其运行时文件放入包内；macOS 将 `smctemp` 可执行文件及经验证必须随附的依赖放入包内。选择单目录而非单文件，便于保留可编辑配置、独立探针和诊断文件，也不要求目标电脑在线安装依赖。

构建器提供明确的目标系统和架构检查，拒绝构建与当前构建机不匹配的 Python 包。首版支持当前项目已验证的 Windows x64 和构建机原生 macOS 架构；其他架构只在单独构建与验收后声明支持。不保证从较新操作系统构建的包可运行于较旧系统。

## 目录布局与用户流程

构建工具从项目源代码运行，输出到 `dist/<platform>-<arch>/`。包内包含：

- `app/`：PyInstaller 单目录应用及依赖；
- `bin/`：Windows 自包含 `TemperatureProbe.exe` 发布目录，或 macOS `smctemp` 及必需依赖；
- `config.example.toml`：按目标平台写好的配置模板；
- `check` 与 `run` 启动脚本（Windows 使用 `.cmd`，macOS 使用 `.command`），只在该进程内把包内 `bin/` 放进 `PATH`，并从包目录读取 `config.toml`；
- `README.txt`：目标机准备、配置、只读检查、运行与停止步骤，以及驱动和安全限制。

构建时不读取、复制或搜索 `.secrets/` 和现有 `config.toml`。包内不含 token，也不含预设的私有配置。用户在目标机复制 `config.example.toml` 为 `config.toml`、填写 IP，并在 `.secrets/purifier-token` 写入自己的 32 位十六进制 token。先运行只读 `check`；确认传感器与设备正常后，用户在场时手动运行 `run`。程序停止后的净化器状态仍由用户管理，打包功能不改变现有控制策略。

## 构建器行为与失败处理

构建器检查 Python 版本、打包依赖、目标平台与架构、Windows 的 .NET SDK 或 macOS 的 `smctemp`。缺少必要组件时给出具体错误。使用临时构建目录，待全部步骤成功、目录结构与必要可执行文件核对无误后，才把结果发布为最终目录；不覆盖非空的既有输出，不清除用户数据。构建失败后不留下貌似可用的最终包。

外部程序调用使用参数数组而非 shell 拼接；不把 token 放入环境变量、命令参数、日志或构建元数据。生成包时检查已知敏感文件路径未被复制，并验证模板仅含公开默认值。Windows 探针自包含发布失败、macOS `smctemp` 依赖不可迁移或第三方许可材料不齐时构建失败并说明原因。

## 验证

单元测试覆盖平台判定、目录布局、启动脚本路径、模板平台值、拒绝覆盖非空输出、失败时不发布成品，以及排除 token / 私有配置。CI 或构建机上的离线冒烟测试运行包内可执行程序的帮助入口，不连接真实净化器。分别在 Windows x64 和 macOS 原生架构上构建并验证包内容；在干净目标机复制目录后手动执行 `check`，验证无需 Python、.NET Runtime 或 `smctemp` 安装。真实 `run` 验收遵循项目 `AGENTS.md`：用户在场、先记录状态、短时运行、停止、恢复、读回。未完成相应平台的实机验收时，只报告构建和离线冒烟结果，不宣称“复制即用”已获该平台验证。
